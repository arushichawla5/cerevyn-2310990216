Compares NDVI for one farm across two dates. It excludes invalid pixels instead of guessing values, compares
the dates only on farm pixels valid on **both** dates, flags a decline using a configurable threshold, and
exports a heatmap, JSON and CSV. **The bundled data is synthetic.**

## Approach

NDVI = (NIR - Red) / (NIR + Red), computed in `ndvi_monitor/core.py`.

A pixel gets an NDVI value only if all of these hold; otherwise it is `NaN` (never 0):

1. its validity mask is True (False = cloud/invalid),
2. both bands are finite and non-negative,
3. NIR + Red is not zero.

Each excluded farm pixel is counted under exactly one reason: *masked*, *bad value* or *zero denominator*.

Comparison:

- **Comparison area** = farm mask AND has-value on date 1 AND has-value on date 2. Mean NDVI of both dates
  and the mean change are computed on this same set, so a cloud on one date cannot bias the difference.
- Per-date valid coverage = valid farm pixels / farm pixels (each date, on its own).
- **Decline flag** (all thresholds configurable):
  - `insufficient_data` if fewer than `min_usable_fraction` (default 0.50) of farm pixels are usable on both
    dates, or none are. No numeric verdict is given in that case.
  - `decline_flagged` if mean change <= `-decline_threshold` (default 0.05).
  - otherwise `no_decline_flagged`.
  - Also reports pixels whose own change <= `-pixel_decline_threshold` (default 0.10).
- Mean change is a field-wide average, so a localised loss can be diluted below the threshold. The pixel
  count and the heatmap are there to show that.

**Interpretation:** an NDVI decline does not by itself establish disease, cause or yield loss. Clouds, haze,
sun angle, sensor differences and crop growth stage also change NDVI. The tool says this in every result
(`interpretation_note`) and on the dashboard.

## Setup

Requires Python 3.12. Dependencies are pinned in `requirements.txt` (numpy 2.5.4, fastapi 0.148.0,
uvicorn 0.54.0, pillow 13.0.0); tests add pytest 9.1.1 and httpx 0.28.1 (`requirements-dev.txt`).

```bash
pip install -r requirements-dev.txt
```

## Run

Dashboard and API:

```bash
uvicorn ndvi_monitor.api:app --port 8000
```

Open http://127.0.0.1:8000 - it analyses the synthetic sample on load. Change thresholds, or upload your own
`.npz`, then press Analyse. Download buttons give `results.json`, `change.csv` and `change.png`.
API docs: http://127.0.0.1:8000/docs.

Command line (writes `results.json`, `change.csv`, `date1_ndvi.png`, `date2_ndvi.png`, `change.png`):

```bash
python -m ndvi_monitor.cli --out outputs
python -m ndvi_monitor.cli --input my_scene.npz --decline-threshold 0.08
```

Docker:

```bash
docker build -t ndvi-monitor .
docker run -p 8000:8000 ndvi-monitor
```

### Input format

An `.npz` with seven 2-D arrays of identical shape: `red1`, `nir1`, `valid1`, `red2`, `nir2`, `valid2`
(validity masks, True = usable) and `farm` (True = inside the farm). Wrong or missing arrays are rejected
with HTTP 422 and a message naming the problem.

| Endpoint | Purpose |
|---|---|
| `GET /api/sample` | Analyse the bundled synthetic sample |
| `POST /api/analyze` | Raw `.npz` body (max 5 MB). Query params: `decline_threshold`, `pixel_decline_threshold`, `min_usable_fraction` |
| `GET /api/sample/{change.png,date1.png,date2.png,results.json,change.csv}` | Direct downloads |
| `GET /api/health` | Liveness |

## Sample data and expected output

`sample_data/farm_two_dates.npz` is generated by `scripts/generate_sample.py` (seed 42) - see
`sample_data/README.md`. Scenario: 20x20 grid, 240 farm pixels, a different 20-pixel cloud on each date, one
pixel with red = nir = 0 on date 1, and a 6x6 patch (36 pixels) whose NDVI falls from about 0.70 to 0.30.

Hand-derived expectation: usable = 240 - 20 - 20 - 1 = **199** pixels (82.92%); declined pixels = **36**.

Actual output (`sample_data/expected_results.json`, default settings):

```
status=decline_flagged  mean_ndvi_date1=0.6971  mean_ndvi_date2=0.6186  mean_change=-0.0785
usable=199 (82.92% of farm)  declined_pixels=36 (18.09% of usable)
date1 coverage 91.25%   date2 coverage 91.67%
```

Heatmap legend: grayscale, dark = decline, mid-gray = no change, light = increase; magenta = farm pixel with no
NDVI value; dark blue-gray = outside the farm.

## Limitations

- Sample data is synthetic and tiny; no real-imagery reader (GeoTIFF) is included, input is `.npz`.
- Whole-farm mean change can hide localised decline; use the pixel statistics and heatmap.
- No atmospheric correction, cloud detection or co-registration - masks and alignment are assumed supplied.
- Negative reflectance is treated as invalid rather than clipped.
- Azure design only (`docs/azure-plan.md`); no cloud deployment was made.
